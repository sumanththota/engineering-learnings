# Superseded Learnings stay, marked forward; old links are never back-edited

When a Learning needs a better phrasing or correction, we write a new file rather than editing the old one in place (ADR 0003). We decided the old file is never deleted — it gets `superseded_by: <new-id>` in its frontmatter, keeping both the file and its git history intact for a personal archive. We also decided other files' existing `links:` entries pointing at the superseded id are never back-edited to repoint at the new one; `superseded_by` is the forward breadcrumb instead. Forcing every historical reference to be hunted down and repointed would reintroduce the manual-sync drift already rejected for `confidence` (ADR 0002). Retrieval should treat a superseded Learning as lower-priority, not hidden.
